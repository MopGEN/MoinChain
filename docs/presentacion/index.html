    Una bitácora que no se puede reescribir

    EL PROBLEMAUn log se edita sin dejar rastro

    El servicio de usuarios ya anotaba cada inicio de sesión, alta y baja, pero solo como líneas de texto. Quien tenga acceso al servidor puede cambiar una línea y nadie lo nota.

    evento=LOGIN_FALLIDO correo=… motivo=PASSWORD_INCORRECTA
    evento=LOGIN_EXITOSO usuarioId=… rol=ADMIN
    ← ¿quién editó esta línea? No hay forma de saberlo.

    LA HERRAMIENTA · SHA-256Una huella digital

    Cualquier texto se convierte en 64 caracteres. Cambia una sola letra y la huella cambia por completo. Pruébalo:

    HUELLA DEL TEXTO ORIGINAL
    HUELLA DE TU TEXTO (EN ROJO, LO QUE CAMBIÓ)
    Criptografía · La estructura

    Cada bloque apunta al anterior

    hash_actual = SHA-256( id | timestamp | datos | prev_hash )

    Una fórmula, en una clase

    Une los cuatro campos con “|” y calcula su SHA-256 en UTF-8. El tiempo va en milisegundos porque MongoDB no guarda más precisión.

    // id | timestamp(ms) | datos | prev_hash
String entrada = id + "|" + timestamp.toEpochMilli()
    + "|" + datos + "|" + prevHash;
MessageDigest digest = MessageDigest.getInstance("SHA-256");
byte[] resumen = digest.digest(
    entrada.getBytes(StandardCharsets.UTF_8));
return HexFormat.of().formatHex(resumen);  // 64 hex

    Tres preguntas por bloque

    Recorre toda la cadena y no se detiene en el primer error: reporta cada bloque dañado y por qué.

    for (BloqueAuditoria bloque : bloques) {
  // 1. ¿falta un número de bloque?
  if (bloque.id() != idEsperado)        BLOQUE_FALTANTE
  // 2. ¿cambió su contenido?
  if (!recalculado.equals(hashActual)) HASH_ALTERADO
  // 3. ¿apunta al hash del anterior?
  if (!hashAnterior.equals(prevHash))  ENLACE_ROTO
  hashAnterior = bloque.hashActual();

    Criptografía · Alcance

    Lo que sí logra y lo que no es

    Logra

    • Detecta cualquier cambioDatos alterados, bloques borrados o enlaces rotos; dice qué bloque y por qué.
    • PersisteLos bloques siguen en MongoDB al reiniciar el servicio.
    • No estorba al loginSi la cadena falla, el inicio de sesión sigue y el error queda en el log.
    • Está comprobadaOtro programa (Node.js) calcula el mismo hash que Java.

    No es una blockchain completa

    • Un solo nodoSin consenso, sin red P2P y sin minería.
    • Sin firma digitalPrueba que no cambió, no quién lo escribió.
    • Reescritura totalQuien controle toda la base puede recalcular todos los hashes.
    • Truncado finalBorrar los últimos bloques no se nota sin una referencia externa.

    Mejoras posibles: firmar cada bloque (ECDSA o Ed25519), anclar el último hash fuera de la base, replicar la cadena en varios nodos y agrupar bloques en un árbol de Merkle.

    El valor del proyecto

    Qué ganamos y qué nos costó

    Ganamos

    • Piezas independientesCada servicio con su base y su contenedor.
    • Datos separadosUn usuario de base de datos por servicio.
    • Nadie espera a nadieSe comunican con mensajes, no con llamadas.
    • Todo o nadaReserva atómica; los mensajes repetidos se ignoran.

    Nos costó

    • Confirmación con retrasoLa venta pasa por “en proceso”.
    • Sin “outbox”Un aviso podría perderse si RabbitMQ falla justo al guardar.
    • Confianza en la red internaNo hay cifrado entre servicios.
    • Sesión de 24 horasSin cancelar un token individual.

    No medimos tiempo ahorrado. Lo que demostramos es independencia entre piezas, y entendimos cuánto cuesta.
